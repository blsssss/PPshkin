# Сценарии проверки ППшкин

Пошаговые сценарии с ожидаемым результатом каждого шага. Тексты реплик взяты из кода бота (`backend/src/bot/texts.ts`, `backend/src/bot/guest/offer-texts.ts`, `backend/src/bot/venue/texts.ts`, `backend/src/notifications/texts.ts`), угловые скобки обозначают значения, которые меняются от запуска к запуску: `<код>`, `<позиция>`, `ЧЧ:ММ`. Кнопки записаны в «кавычках».

| Сценарий | Кто | Где |
|---|---|---|
| A. Гость в боте | гость | бот в MAX |
| B. Гость в мини-приложении | гость | мини-приложение в MAX |
| C. Заведение на своём аккаунте | заведение и гость на одном аккаунте | бот в MAX |
| D. Проверка через API с демо-токенами | демо-гость и демо-заведение | HTTP API |
| E. Ошибки и восстановление | гость и заведение | бот, мини-приложение, API |

Подготовка:

- Бот: [https://max.ru/t516_hakaton_max_bot](https://max.ru/t516_hakaton_max_bot) («Хакатон МАХ 516»), подходит любой аккаунт MAX, мобильное приложение или веб-версия `https://web.max.ru`. Мини-приложение: кнопка запуска в чате с ботом или [https://max.ru/t516_hakaton_max_bot?startapp](https://max.ru/t516_hakaton_max_bot?startapp).
- Сервер работает в демо-режиме (`DEMO_MODE=true`): все заведения, меню, акции и история аналитики тестовые и помечены «Заведение и меню тестовые». Данные пересоздаются ежедневно в 06:00 по Москве.
- Время: кофейня «Зерно» и её копии работают с 08:00 до 22:00 по Москве, кофейня «Пенка» круглосуточно. Бронь возможна только в открытом заведении, поэтому сценарий C проходите в часы работы «Зерна».
- Кнопки открытия мини-приложения в сообщениях бота появляются при `MINI_APP_ENABLED=true` на сервере; без них остальные шаги не меняются.
- Для локальной проверки API: `docker compose up -d --build --wait` из корня репозитория, подробности в [README.md](../README.md).

## D. Проверка через API с демо-токенами

Те же шаги запросами к API. На сервере адрес `https://<домен>/api/v1` (сейчас в документации заполнитель `https://ppshkin.example.com`, он будет заменён на рабочий после развёртывания по [deploy.md](deploy.md)), Swagger UI `https://<домен>/docs`, контракт [openapi.yaml](../openapi.yaml), машиночитаемый набор проверок [DATA-API.yaml](../DATA-API.yaml). Значения `DEMO_GUEST_TOKEN` и `DEMO_VENUE_TOKEN` сервера передаются жюри вне репозитория. Локально:

```bash
BASE=http://localhost:3000
GUEST="Authorization: Bearer local-demo-guest-token-not-secret"
VENUE="Authorization: Bearer local-demo-venue-token-not-secret"
```

Для сервера `BASE=https://<домен>` и токены сервера. Уведомления бота демо-учёткам не отправляются: у них отрицательные `userId`, это не пользователи MAX.

| № | Запрос | Ожидаемый результат |
|---|---|---|
| D1 | `curl -s $BASE/health` и `curl -s $BASE/ready` | `200 {"status":"ok"}` и `200 {"status":"ready"}` |
| D2 | `curl -s -i $BASE/api/v1/me` | `401`, `content-type: application/problem+json`, тело с `type`, `title`, `status`, `code` `unauthorized`, `detail` |
| D3 | `curl -s -H "$GUEST" $BASE/api/v1/me` | `200`: `id` `-1001`, `kcalTarget` 1800, `goal` `maintain`, `dislikedTags` `["fish"]`, `consents.personalData.granted` `true` |
| D4 | `curl -s -H "$GUEST" $BASE/api/v1/diary/today` | `200`: `date`, `targetKcal` 1800, `totals`, `remainingKcal`, `meals` |
| D5 | `curl -s -X POST -H "$GUEST" -H "Content-Type: application/json" -d '{"title": "Капучино", "kcal": 120}' $BASE/api/v1/diary/meals` | `201`: `id`, `title` `Капучино`, `kcalMin` 120, `kcalMax` 120, `source` `manual`, `slot` |
| D6 | то же с телом `{"title": ""}` | `400 application/problem+json`, `code` `validation_failed`, `errors` с путями `body.title` и `body.kcal` |
| D7 | `curl -s -X POST -H "$GUEST" -H "Content-Type: application/json" -d '{"description": "съел борщ и кусок хлеба"}' $BASE/api/v1/diary/meals/text` | `200`: `status` `logged`, записи и итоги дня `day`. Без ключа ChadGPT `basis` «Оценка по справочнику типичных порций», запись «Борщ», 180-280 ккал |

## E. Ошибки и восстановление

| № | Действие | Ожидаемый результат |
|---|---|---|
| E1 | Отправить боту фото не еды | «Похоже, на фото не еда. Пришлите фото блюда или напишите, что съели, например: Сырники 350» с кнопкой «Ввести вручную» |
| E2 | «Ввести вручную», затем `Сырники 350` | «Напишите название и калории, например: Сырники 350» с кнопкой «Отмена»; после ответа «Записал: Сырники, около 350 ккал» и остаток на день |
| E3 | Отправить стикер, голосовое сообщение или видеокружок | На стикер: «Я понимаю фото еды и текст, например: Сырники 350. Все возможности: /help». Голосовые и видеокружки бот не распознаёт: платформа присылает для них пустые обновления. Допущение, не проверенное на всех клиентах MAX: на такое пустое сообщение бот отвечает той же подсказкой |
| E4 | Любое сообщение до согласия на обработку данных | Запрос согласия с кнопками «Согласен» и «Подробнее»; на нажатие кнопки всплывает «Сначала нужно согласие на обработку данных» |
| E5 | `/venue`, «Погасить код», отправить `12345` | «Код состоит из 6 латинских букв и цифр, попробуйте ещё раз» с кнопкой «Отмена» |
| E6 | Отправить несуществующий код `AAAAAA` | «Бронь с таким кодом не найдена в вашем заведении. Проверьте код и введите его ещё раз.»; бот ждёт следующий ввод. В API `404` `booking_not_found`, в мини-приложении «Бронь с таким кодом не найдена в вашем заведении», при сканировании чужого QR «Это не QR брони ППшкин» |
| E7 | Дождаться окончания брони (60 минут, конец акции или закрытие заведения) | Задача `expire_bookings` в течение минуты переводит бронь в `expired`, порция возвращается в горящую позицию. Гостю приходит «Бронь <код> истекла в ЧЧ:ММ: <позиция>, <заведение>. Код больше не действует.» с кнопкой «Подобрать другое»; в мини-приложении «Время брони вышло» и «Найти другое» |
| E8 | Погасить истёкшую бронь | Бот: «Срок брони истёк. Гость может оформить новую»; API `409` `booking_expired`; уже погашенная или отменённая бронь: «Бронь уже погашена или отменена», `409` `booking_not_active` |
| E9 | Забронировать в закрытом заведении | Бот: «Заведение сейчас закрыто, бронь не получится. Посмотрим другое: /eat»; API `409` `venue_closed`; мини-приложение «Заведение сейчас закрыто, бронь недоступна» |
| E10 | ChadGPT не ответил или ключа нет | «Сервис распознавания не ответил. Попробуйте через минуту или напишите вручную, например: Сырники 350» или «Распознавание фото сейчас выключено. Напишите, что съели, например: Сырники 350» с кнопкой «Ввести вручную». Повтор без перезапуска: отправить фото ещё раз через минуту или записать вручную |
| E11 | Больше 20 распознаваний за час | «Слишком много запросов подряд. Попробуйте через час или запишите вручную, например: Сырники 350»; ручная запись работает |
| E12 | Нажать кнопку старого сообщения или ту же кнопку повторно | Всплывает «Кнопка устарела» или «Эта кнопка уже нажата», действие не повторяется. Повторная доставка того же обновления MAX отбрасывается по ключу в `processed_updates`, запись не дублируется |
| E13 | Непредвиденная ошибка в боте | «Что-то пошло не так. Попробуйте ещё раз или отправьте /help»; следующее сообщение обрабатывается как обычно, перезапуск не нужен |
| E14 | Ошибка загрузки в мини-приложении или истёкшая сессия | Экран с кнопкой «Повторить», повторный запрос без перезагрузки; при устаревших данных запуска «Сессия устарела» и «Закройте мини-приложение и откройте его снова.» |
| E15 | Превышение лимита API | `429 application/problem+json` с заголовком `Retry-After`; после паузы запросы проходят |
| E16 | `docker compose restart backend` на локальном стенде | Через несколько секунд `/ready` снова отвечает `{"status":"ready"}`, данные на месте, миграции и демо-данные проверяются идемпотентно |

Формат ошибок, лимиты и фоновые задачи описаны в [architecture.md](architecture.md).
